# talk-deck — 목요일 발표자료 만들기

목표: 수강생이 **한 문장**으로 시작해서 **10분 발표용 웹 슬라이드 링크**를 받는다. 재료는 비서가 모으고, 이유와 소감은 사람이 말한다.

`{baseDir}` = 이 SKILL.md 가 있는 폴더. 작업 폴더 `<ws>` = 이 에이전트의 워크스페이스. 산출물은 `<ws>/talk/w<주차>/` 에 둔다.

## 1주차 발표 구성 (1인 10분)

참여 동기(30초) → ① 내가 생각하는 에이전트 팀과 구조도(2분) → ② 팀 멤버 소개(작아도 괜찮음) + 앞으로 구성하고 싶은 팀(2분) → ③ 대시보드 리뷰 + 앞으로 구성하고 싶은 대시보드(2분) → 가상 오피스(1분) → ④ 1주차 소감(1분) → 한 달 뒤 완성하고 싶은 것(40초) → 다짐과 선언(40초).
슬라이드 순서: 표지 → 순서 → 참여 동기 → 업무 지도 → 구조도 → 멤버 → (총괄 자기소개) → 앞으로의 팀 → 대시보드 → 써 보니 → 앞으로의 대시보드 → 가상 오피스 → 소감 → 한 달 뒤 → 다짐과 선언 → 감사. 비어 있는 장은 자동으로 빠진다.

## 0. 시작 전에 사용자에게 한 번 알린다

"발표자료를 만들게요. 제가 업무 지도·팀·대시보드 기록을 먼저 읽고 초안을 만든 뒤, 꼭 본인 말이 필요한 것만 두 번에 나눠 여쭤볼게요. 다 되면 미리 확인받고 베이스캠프 발표장에 올립니다."

## 1. 재료 모으기 (묻지 않고 한다)

```bash
node {baseDir}/scripts/collect.mjs --out <ws>/talk/w1/talk.json --week 1
```
- 결과 JSON 의 `found` 에 찾은 파일, `ask` 에 사람에게 물어야 할 칸이 나온다. 못 찾은 파일은 `--root <디렉터리>` 로 다시 찾는다.
- 이어서 직접 읽어 채운다(사람에게 묻지 말고):
  - 각 에이전트 워크스페이스의 `SOUL.md`·`IDENTITY.md` → `members.list[].relation / tone / dislike` (한 줄씩, 짧게)
  - `SOUL.md`·`AGENTS.md` 의 권한(자율/승인/금지) → `structure.permissions`
  - `workMap.rows[].owner` → team.json 의 담당 메뉴·역할로 짝짓기
  - HIA `logs/` 최근 로그 → 막혔던 지점 후보 1~2개(질문할 때 보기로 제시)
  - 가상 오피스: collect 가 `virtual-office/org.json`·`office.html` 을 찾으면 `office` 에 직원·채용 예정·템플릿이 채워진다. 슬라이드는 키트 CDN 배경 위에 캐릭터를 자리대로 앉힌 정지 화면이다. 템플릿을 못 알아냈으면 묻는다. 가상 오피스를 안 만들었으면 이 장은 빠진다(억지로 만들지 않는다).
- 제목은 **기대감 있는 한 문장** 2~3안을 만들어 둔다(예: "꽃집 사장이 팀장이 된 첫 주"). 분류명("1주차 발표") 금지.

## 2. 사람에게 묻기 — 두 번만, 한 번에 묶어서

**1차 (내 이야기 — 반드시 본인 말)**
1. 이 과정에 참여한 동기 한 문장 (+ 계기 한 줄)
2. 1주차를 한 문장으로 말하면?
3. 가장 막혔던 곳과 어떻게 풀었는지 (로그에서 찾은 후보를 보기로)
4. 가장 놀랐던 순간
5. 다음 주에 비서에게 맡기고 싶은 일 하나
6. 한 달 뒤 완성하고 싶은 것 한 문장 + 눈에 보이는 결과물 2~3개
7. 그걸 위해 한 달 동안의 다짐 2~3개 + 선언 한 문장 ("나는 4주 뒤 ○○ 하겠습니다")

**2차 (확인·선택)** — 초안을 보여주며 고르게 한다
8. 제목 2~3안 중 선택(또는 직접)
9. 대시보드 며칠 써 보니 좋았던 점·아쉬운 점 (각 1~3개)
10. 앞으로의 팀(2·3·4주차에 늘릴 직원)과 앞으로의 대시보드(채울 메뉴 2~4개) — 비서가 커리큘럼(2주 아침 루틴: 메일·카톡 / 3주 콘텐츠 발행 / 4주 팀 운영·쇼핑몰)에 맞춰 **초안을 제안**하고 고치게 한다
11. 대시보드 장의 ❶❷❸ 설명: 내 업무 메뉴 이름을 왜 그렇게 지었는지, 위젯을 보고 무엇을 하는지
12. (가상 오피스가 있으면) 그 템플릿을 고른 이유 한 줄
13. 테마 선택 (아래 표). "골라줘"면 업무 성격에 맞춰 추천 1개 + 이유 한 줄
14. (선택) 대시보드·가상 오피스 화면 캡처가 있으면 보내 달라 — 없으면 데이터로 다시 그린 화면이 들어간다

규칙:
- 참여 동기·소감 4칸·한 달 뒤 목표·다짐과 선언은 **사용자 문장을 그대로**(맞춤법·길이만 다듬기). 지어내거나 부풀리지 않는다. 막막해하면 예시 1개만 보여 주고 본인 말로 다시 받는다. 답이 없으면 그 칸은 비운다(장이 빠진다).
- 숫자·사실은 기록에 있는 것만. 없는 수치를 만들지 않는다.
- 토큰·비밀번호·개인 연락처는 넣지 않는다(빌드가 막는다).

| 테마 | 키 | 느낌 | 제목 글꼴 |
|---|---|---|---|
| 페이퍼 | `paper` | 따뜻한 미색 종이, 잡지 같은 차분함 | 고운바탕 |
| 미드나잇 | `midnight` | 어두운 무대 + 네온 포인트, 테크 발표 | Pretendard Black |
| 보태니컬 | `botanical` | 초록·테라코타, 가게·공방 같은 따뜻함 | 나눔명조 |
| 팝 | `pop` | 원색 블록·굵은 테두리, 에너지 | 검은고딕 |
| 미니멀 | `minimal` | 흰 여백 + 파랑 한 색, 깔끔한 보고서 | Pretendard |

본문은 모두 Pretendard. 예시 5종: https://run-academy.pages.dev/s4/talks/examples/ (저장소 `examples/flower/decks/` 와 같음).

## 3. 만들기

`<ws>/talk/w1/talk.json` 을 채운 뒤(형식: `references/talk-schema.md`):
```bash
node {baseDir}/scripts/build.mjs --talk <ws>/talk/w1/talk.json --theme <key> [--screenshot <대시보드 캡처.png>] [--office-screenshot <가상 오피스 캡처.png>] --out <ws>/talk/w1/deck.html
```
- `warnings` 가 있으면 사용자에게 한 줄로 알리고 채울지 묻는다.
- 발표자 노트(`notes`)에 장마다 "이렇게 말해 보세요" 한두 문장을 넣는다(N 키로 보임). 사용자 말투로.

## 4. 확인받고 올리기

사용자에게 장 목록(제목만)과 테마를 보여주고 **"베이스캠프 발표장에 올릴까요? (같은 기수 모두가 볼 수 있어요. 다시 올리면 덮어써요)"** 라고 묻는다. 승인 후:
```bash
node {baseDir}/scripts/publish.mjs --deck <ws>/talk/w1/deck.html --title "<제목>" --theme <key> --week 1 --name "<베이스캠프 명단의 이름>"
```
- **처음 올릴 때만** "베이스캠프에 등록된 이름 그대로 알려 주세요"라고 이름을 묻는다(질문 1차에서 받아 둬도 된다). 토큰·코드는 필요 없다.
- 처음 올리면 서버가 **수정 열쇠**를 주고 스크립트가 `~/.config/run-academy/talk.json`(600)에 이름과 함께 저장한다. 다음부터는 `--name` 없이도 같은 이름·열쇠로 덮어쓴다. 열쇠는 대화·로그에 출력하지 않는다.
- 성공하면 `url`(내 발표)과 `galleryUrl`(발표장)을 전한다. "발표장에서 ← → 로 넘기고, F 전체화면, N 노트예요."
- 종료 코드 6(404): 명단에서 이름을 못 찾음 → 베이스캠프에 등록된 이름(띄어쓰기 무관)을 다시 묻는다.
- 종료 코드 4(403): 이 이름으로 이미 다른 곳에서 올렸고 열쇠가 다름(예: 서버를 새로 만들어 talk.json 이 사라짐) → "운영진에게 발표장 열쇠 초기화를 부탁해 주세요"라고 안내. 409 는 동명이인 → 운영진에게.
- 2주차에 광장 에이전트를 등록해 토큰(`rap_s4_…`, 환경변수·`~/.config/run-academy/plaza-token`·광장 스킬 `plaza.env`)이 있으면 스크립트가 자동으로 토큰 방식을 쓴다.
- 3·5(네트워크·서버): 1회 재시도 후에도 실패하면 deck.html 을 사용자 PC 로 보내거나(노드 연결 시) 베이스캠프 과제 탭에 파일로 내라고 안내.

## 5. 고치기

"제목 바꿔줘", "테마를 팝으로", "소감 고쳐줘" → talk.json 수정 → build → (승인 받은 적 있으면 바로) publish. 같은 주차는 덮어쓴다.

## HIA 기록

작업 끝에 프로젝트 `logs/` 에 한 줄: 만든 날짜·테마·장 수·게시 링크(토큰 제외). 사용자 확정/실행/검증을 구분해 쓴다.
